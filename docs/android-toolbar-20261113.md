# Android 工具条、悬浮窗与分辨率（2026-11-13）

- 正常窗口保留底部工具条；网页悬浮和原生 Document PiP 使用右侧工具条，常用操作纵向滚动，窗口操作固定在右侧底部。
- 替换不存在的 bg-secondary/bg-tertiary/bg-primary/border-color 变量，使用项目 bg-surface/bg-elevated/bg-base/border-subtle。原生 PiP 监听主页面主题变化并同步颜色变量。
- 去除重复的 Android / WebCodecs 信息，仅保留连接状态点，画面尺寸作为分辨率入口。
- 网页悬浮窗按 border-box 定位，缩放时保持左上角锚点并限制在完整视口边界；可拖到视口底边。新增“铺满窗口”，原生 PiP 点击时把同一个视图转移回页面并铺满；不重建连接。页面全屏入口保留。原生窗口的操作系统边界和浏览器尺寸策略不能由网页解除。
- 分辨率面板提供小屏 720×1280、经典 1080×1920、全面屏 1080×2400、大屏 1440×3200、自定义及设备默认。通过 Go ADB 调用 wm size 修改 Android 的显示尺寸；尺寸范围 320–4096，摄像头模式禁止修改。它不是精确模拟某品牌手机的 DPI/性能。编码流仍使用既有 max_size=1280，界面显示的是传输画面尺寸，提示中说明了缩放。
- 旋转指令保持不变。

## 测试

17 项 Android 客户端/悬浮窗前端测试通过；Go TestAndroid 测试通过，包含分辨率参数校验。前端生产、原生 server/gateway 构建通过。全量类型检查仍有既存错误，本次 AndroidTabContent/useFloatingWindow 无错误。

真实 redroid + Chromium：1080×1920 预设写入远端 Override size，恢复默认后 override 消失；工具条位于画面右侧；拖动后悬浮窗底边等于 1000px 视口底边；铺满后为 (0,0,1440,1000)；全屏成功；恢复后 Home 可用；无浏览器异常。

真实 Document PiP：右侧布局正确；主页面由浅色切换深蓝后，PiP 工具条颜色实时改变；铺满按钮转回主页面且尺寸为 1440×1000，无需重连。

截图、脚本、测试日志保存在同目录。首次测试选用与设备原生相同的 720×1280，Android 不生成 override，因此正式验证改为 1080×1920。
