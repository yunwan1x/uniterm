# Android 设备显示、视频画质与窗口显示

设备预设/尺寸/DPI 保留在「设备显示」。新增独立「视频画质」面板：自动（默认）、最长边 1280/1920/2560、原生；15/30/60 FPS；2/4/8/12/20 Mbps。设置按设备地址和端口保存在当前浏览器。应用重建当前 Android 会话；相机源切换和重连沿用选择。

Android 的连接生命周期改由内容组件负责，首次挂载后测量窗口并读取画质设置。自动最长边使用可视区域 CSS 尺寸乘 DPR、16 对齐，限制 640–2560；只在连接时计算，不因窗口拖动频繁重连。后端验证参数范围；未传配置的旧客户端仍使用 1280/30 FPS/4 Mbps。原生传递 max_size=0，最终输出仍取决于设备捕获和编码能力。

窗口显示增加「适应窗口 / 实际像素」，保留全屏、悬浮窗、铺满窗口；网页悬浮窗增加底边和右边拖动区，分别仅改变高度/宽度。原生 PiP 窗口仍由浏览器控制尺寸。

## 验证

- Go Android 测试通过，覆盖原生无上限、旧默认和非法编码参数拒绝。
- 47 项前端测试通过，含连接初始化路径、边缘单轴拖动、客户端和既有悬浮窗行为。
- 前端生产构建与 server production 构建通过。全量类型检查仍有 570 个既存错误，本次新增代码未增加错误。
- Chromium + 当前 redroid 真实端到端测试：自动初次连接 424×912；1280 档 592×1280；1920 档 888×1920；2560 档 1184×2560；原生 1184×2560。原生模式不承诺达到设备请求尺寸，展示实际接收尺寸。
- 实际像素画布高度 2560 CSS px；适应窗口缩小至视口内。底边拖动后窗口底边精确到 1000px 视口底部，宽度不变。
- 重载页面再连接后恢复保存的原生画质并收到 2560 高画面；浏览器无 pageerror。
- 测试前后 wm size 一致：Physical 1440×2560、Override 1440×3120；未修改设备尺寸/DPI。redroid 保持运行。

原生模式的实际捕获尺寸限制与浏览器画布缩放分别处理；本次没有测量持续视频播放的帧率或码率达标情况。自动化测试证据位于 ../artifacts/android-quality-20261113（仓库外）。
