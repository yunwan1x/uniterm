# RDP Web 文件传输验收（2026-11-13）

已实现状态栏「文件」按钮与浮动面板；全屏工具栏也使用同一入口。上传选择/拖入本地文件后，到远端目录粘贴；远端复制文件后，面板勾选并明确点击下载。任务包含进度、取消、重试、清理；收起面板不会销毁传输。网页文件通过 CLIPRDR 传输，不落盘到 uniTerm 服务端。

## 实机结果

隔离 Linux xrdp + xorgxrdp + FUSE、Thunar，Chromium 通过实际 uniTerm Web Worker/WASM 会话验证：

- 上传：2,097,408 字节二进制文件 `local-fixed-你好.bin`，实际在远端 Thunar Ctrl+V；本地和远端 SHA-256 均为 `f465f6f85e7e62111b5aa8ac9e5b442cab2bdd53802e2f070bfd8f4846468ee2`。
- 上传空文件：远端创建成功，面板完成状态正确。
- 下载：远端 clipboard 提供空文件与中文名二进制文件。只勾选第二项，实际浏览器下载 `remote-你好.bin`，源文件和下载文件 SHA-256 均为 `ad4707187ce2c9c3d16909bd20eb1c440fa9d2717bff5b836db2d32f997da4d2`。
- 上传取消→重试→收起面板→远端粘贴→重新打开：任务完成，远端字节内容核对通过。
- 760×700 窗口中面板边界检查通过。

首次实测发现 xrdp 即使未协商 CAN_LOCK_CLIPDATA 也附带 clipDataId=0。IronRDP 原本把它当未知锁并拒绝读取，Thunar 出现错误内容文件。修复为只在未协商锁功能时忽略该字段；已协商情况下继续拒绝未知锁。新增协议回归测试同时覆盖这两种情况，修复后重新上传通过完整哈希校验。

## 限制

浏览器单文件下载最多 256 MiB，以限制内存占用；文件夹暂不支持。上传完成表示文件字节已发送，协议无法保证远端应用最终落盘。下载完成表示交给浏览器，最终保存由浏览器处理；多文件可能需要允许连续下载。远端需开启剪贴板文件重定向，Linux xrdp 需要 FUSE 支持。Windows 本轮没有实机复测；保留其锁协议校验并通过协议回归，不代替 Windows 验收。
